# CRYSTAL UX MASTERPLAN

Mission ID: UX-REBUILD-MASTER
Status: Strategy only. No implementation.

## Objective
Rebuild Crystal OS as a modern operational platform that is simple, fast, beautiful, and role-optimized.

## Strategic Direction
- Replace fragmented UI with one operating system experience.
- Make workflows primary and data views secondary.
- Turn dashboards into decision engines.
- Prioritize technician field execution above all roles.

## Research Conclusions Applied
- Simplicity comes from fewer decisions per screen, not fewer features.
- Premium feel comes from restraint, spacing, readability, and content precision.
- Speed is UX: keyboard-first for office roles, thumb-first for field roles.
- Best products unify search + command + context instead of deep menus.

## Major UX Problems Identified
- Dashboard fragmentation and duplicate entry points.
- ERP-style navigation causing cognitive overload.
- Non-uniform component patterns and visual rhythm.
- Technician flows with too much friction and typing risk.
- Customer surfaces with inconsistent trust/premium quality.

## Rebuild Sequence (Must-Rebuild-First)
1. Technician field core workflow (highest business/operational impact)
2. Admin command center and exceptions workflow
3. Secretary speed workflows (search, quick create, scheduling, invoicing)
4. Customer premium portal
5. Secondary/edge modules and expert-mode screens

## Workstream Structure

## Stream A: OS Foundations
- Design tokens
- Navigation system
- Component library
- Accessibility baseline

## Stream B: Role Experiences
- Admin
- Secretary
- Technician
- Customer

## Stream C: Interaction Infrastructure
- Universal search model
- Command palette action model
- Notification and escalation model

## Stream D: Quality and Governance
- UX acceptance criteria by role
- Click-budget audits
- Accessibility audits
- Field usability validation

## Role Outcomes
- Admin: 5-7 actionable command cards, no decorative widgets.
- Secretary: fastest path for search/create/schedule/invoice.
- Technician: one-handed, high-contrast, low-typing, offline-aware.
- Customer: premium trust-first portal with only essential information.

## Device Strategy
- Mobile-first architecture baseline.
- Tablet optimized for dispatch and coordination contexts.
- Desktop optimized for command and high-level control.

## Non-Negotiables
- Max 3 navigation levels.
- Max 2 clicks to daily tasks.
- Every dashboard card is actionable.
- Every screen answers where/attention/next action.

## Success Metrics
- Time-to-first-action per role reduced.
- Click count for top 10 tasks reduced.
- Technician completion time reduced.
- Customer payment and communication completion improved.
- Admin exception resolution latency reduced.

## Approval Gate
No UI implementation starts until all nine design strategy documents are approved by CTO.
